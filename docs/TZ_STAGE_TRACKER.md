## Статус по этапам

### `14.1` Проектирование — `completed`

- собрана новая доменная модель CRM
- выделены отдельные `crm-api` и `crm-web`
- описаны ключевые модули и структура БД

### `14.2` Базовая инфраструктура — `in_progress`

- есть Express + Prisma foundation
- есть Next.js mobile-first shell
- есть Docker Compose
- поднят backend catalog permission codes и CRUD foundation для ролей
- живой экран `/users` уже читает роли и матрицу прав из новой БД
- еще не готовы auth, полноценный RBAC enforcement, seed SaaS owner и migrations-first bootstrap

### `14.3` Клиенты и парк — `in_progress`

- подключен legacy bridge к старой CRM
- сделан импортный экран `/imports`
- добавлены dry-run import jobs
- добавлен commit import client/bike/deal stubs в PostgreSQL
- добавлены live lists для клиентов и велосипедов из новой БД
- добавлена синхронизация профиля клиента из реального контрагента МойСклад по `legacyReference`
- в карточку клиента и документный контур уже подтягиваются реальные поля из максимально заполненных контрагентов: ФИО по частям, телефон, дата рождения, пол, паспортные данные, адреса, Telegram
- добавлено отдельное поле `Место работы` для договора
- на экране `/clients` добавлен справочник `Места работы` с ручным добавлением, удалением и dropdown-выбором у клиента
- в клиента добавлено отдельное поле `ID курьера` с поиском и использованием в документных кодах
- в клиента добавлены рабочие реквизитные поля по реальному примеру: `тип клиента`, `ИНН`, `email`, `факс`, `Макс`, адресные комментарии и `коды ФИАС`
- в клиента добавлен отдельный список `Родственники` с несколькими записями `имя + телефон + комментарий`
- при sync из МойСклад родственники теперь могут автоматически выделяться из старого комментария, если строка явно начинается с телефона
- экран `/clients` переделан в простой список строк вместо карточек: поиск работает по частям слова, а клик по строке открывает окно клиента поверх списка
- из раздела `Клиенты` теперь можно создать нового клиента, а сама карточка клиента переведена в отдельную страницу `/clients/[clientId]` с более компактной формой
- первый безопасный проход клиентского модуля перевел `/clients` в более легкий CRM-реестр: теперь список тянет отдельный payload и показывает `ФИО / сколько денег принес / активные сделки / флаги`
- в клиента добавлены отдельные флаги `проблемный клиент` и `вор / черный список` с отдельным комментарием, а не как обычные теги
- верх карточки клиента теперь показывает `долг / сколько денег принес / дней в аренде / активные сделки`
- карточка клиента дополнена компактными read-блоками `Активные сделки` и `Последние оплаты`, без захода в тяжелые подсистемы
- формы создания и редактирования клиента собраны в отдельные блоки `Основное / Контакты / Адрес / Комментарий / Флаги`
- парк переведен в рабочий реестр, а карточка велосипеда уже показывает честную read-экономику `принес / ремонты / чистая прибыль`
- комплект больше не считается частью велосипеда по умолчанию: в карточке велосипеда теперь показывается только то, что выдано по активной сделке
- еще не готовы полноценные CRUD клиентов и парка

### `14.4` Аренда и выкуп — `in_progress`

- доменные таблицы есть
- live read-экраны аренды и выкупа уже добавлены
- добавлен единый рабочий реестр `/orders`, где аренда и выкуп снова сведены в один список как в исходном дашборде
- import commit теперь создает `payment_schedules` и `payment_schedule_items`
- добавлен backend schedule/debt service для rental / buyout snapshot
- в live-экранах появились preview-графики по первым schedule items
- добавлены detail pages `/rentals/[dealId]` и `/buyouts/[dealId]`
- добавлены backend detail endpoints с графиком, заметками и operational summary
- раздел `/orders` упрощен и возвращен к логике исходного дашборда: компактный рабочий список вместо перегруженных карточек
- в `/orders` добавлен StarLine GPS status как в исходном дашборде
- добавлен короткий mobile-first экран `/orders/new` для оформления новой аренды или выкупа прямо из CRM
- добавлены backend endpoints создания новой аренды и нового выкупа, где тариф берется только из закрепленной группы велосипеда
- базовая арендная группа `700 / 4500 / 15000` массово закреплена за `34` велосипедами `Kugoo Kirin V3 Pro / Monster`
- новый экран `/orders/new` теперь реально стартует на аренде и показывает только подходящие велосипеды по типу сделки
- добавлены простые actions `Возврат велосипеда` для аренды и `Закрыть выкуп` для выкупа с backend-проверкой долга и активных штрафов
- настройки залога и штрафов вынесены из карточек сделок в общий раздел `/tariffs`
- в карточке аренды остались actions приема/возврата залога и начисления штрафов
- в карточке выкупа остались actions оплаты, закрытия и рабочий просмотр текущих правил
- добавлен action `Продлить` в карточке аренды: следующий цикл теперь можно переключить на разрешенный тариф `1 / 7 / 30 дней` только из группы велосипеда
- backend продления обновляет ближайший цикл, cadence графика и следующую сумму без ручного ввода менеджером
- для аренды введена заморозка ставок по сделке: если общая тарифная группа меняется, активный клиент продолжает жить по сохраненной старой стоимости до завершения аренды
- в реестре `/orders` добавлены простые основные статусы: `Аренда`, `Выкуп`, `Аренда завершена`, `Выкуп завершен`, `Проблемы`, `В ремонте`
- `Проблемы` переведены на ручной статус менеджера: просрочка, штрафы и долг больше не включают этот статус автоматически
- в карточках аренды и выкупа добавлен простой action `Проблемы`, который менеджер включает и снимает вручную
- верх `/orders` упрощен до рабочих счетчиков с количеством: `В работе`, `Аренда`, `Выкуп`, `Проблемы`, `В ремонте`, `Простой`
- добавлен новый справочник `Комплекты / доп. оборудование`
- в `Новый заказ` менеджер теперь может выбрать комплект из справочника, и он сохраняется в сделку как отдельный deal-level контур
- комплект уже выводится в раскрытии `Заказов`
- еще не готовы мягкие сценарии `на удержании / готовится возврат`

- поднят отдельный раздел `/tariffs`, где супер-админ создает свои тарифные группы `1 / 7 / 30+`, задает общие штрафы и залог и закрепляет эти группы за конкретными велосипедами
- в `/tariffs` добавлены отдельные группы `Аренда` и `Выкуп`, поле бесплатных дней по ставке и массовое закрепление группы за моделью/партией велосипедов

- в `/banks` добавлена простая mobile-first форма создания банка: название, телефон, режим `QR / реквизиты`, текст и загрузка QR-картинки
- create flow банка уже пишет `bank`, `bank_asset` и QR-файл в storage новой CRM
- еще не готовы penalty payment flow, расходные операции и полный buyout penalty flow

### `14.6` Ремонты и экономика — `in_progress`

- поднят новый backend route `/repairs`
- ремонт теперь открывается отдельным действием менеджера с выбором велосипеда по поиску `по части слова`
- при открытии ремонта велосипед переводится в статус `REPAIR`
- в ремонт можно зайти без суммы и позже добавлять позиции отдельно
- каждая позиция ремонта может сразу списываться с выбранного банка и попадать в `Финансы` как `REPAIR_EXPENSE`
- завершение ремонта переводит велосипед обратно в `AVAILABLE`, то есть в `Простой`
- на фронте запущен простой mobile-first экран `/repairs` без лишней перегрузки
- еще не готовы детальная экономика по велосипеду и расширенная аналитика убыточности

### `14.7` Документы — `in_progress`

- поднят backend модуль `/documents`
- есть реестр шаблонов, каталог кодов и preview values по клиенту / аренде / выкупу
- шаблоны теперь держат собственную автонумерацию `numberPrefix + nextNumber`
- работает draft generation в file storage с привязкой документа к сделке и клиенту
- добавлена загрузка шаблонов `.docx` и `.txt` прямо в новую CRM
- реализован merge кодов внутрь загруженного Word-шаблона и сохранение готового файла
- из карточки аренды и выкупа менеджер уже может выбрать шаблон, сгенерировать документ и скачать его
- данные клиента для договора теперь автоматически подтягиваются из legacy-профиля МойСклад перед генерацией
- в preview values и генерацию документов добавлен код `{{deal.equipment_summary}}` для комплекта, выданного по сделке
- еще не готовы полноценный визуальный конструктор шаблонов и расширенная печатная логика

### `14.8` Уведомления — `in_progress`

- reference logic найдена в старой CRM
- в новой CRM поднят backend `NotificationService` для Telegram-очереди
- после оформления сделки CRM ставит в очередь сообщение с тем, что выбрано у банка: `QR` или `реквизиты`
- если у банка выбран `QR` и загружена картинка, путь к файлу теперь сохраняется в notification queue как вложение для будущего Telegram transport
- после подтвержденной оплаты CRM ставит в очередь следующее сообщение с датой следующей оплаты
- если у клиента не заполнен Telegram, уведомление помечается как `SKIPPED`, а не теряется silently
- еще не готовы реальная отправка через Telegram transport, расписания due/overdue и UI сценариев
